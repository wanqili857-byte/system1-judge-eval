# 判断模型（System-1）域外可用性实测

把「不产生文字、只回答结构化判断题」的小模型（System-1 / 判断模型，代表实现：开源 [Laya](https://github.com/NandhaKishorM/laya)、托管 Jev）接进 agent loop，**到底行不行、边界在哪**——本仓库是这次实测的题集、脚本与结果，配套一篇公开长文。

**结论一句话**：在作者的工作流（Claude Code 的命令执行/结果核验场景）上，322–421M 级本地判断模型**域外全部塌缩为「偏正类」常量分类器**——命令安全漏拦高危、结果核验把失败全判成功；同任务大模型 84.6–100%。**主产出是一张「判断外包边界表」**（见 `results/summary.md` 与长文 §6）。

> ⚠️ 这是一份**单点实测记录**，不是通用评测标准。可迁移的是方法（判断点盘点 / 双裁判标注 / Dawid-Skene 噪声建模 / 五维分流判据），不是这张表本身。

## 后续：T5 微调闭环

T1 结尾留了一个反问——*判据写得这么清楚，手写正则就够了，为什么还要微调？*
`t5-finetune/` 把那个反问做成了实验：同一份判据、同一份题，跑**手写正则 / 未微调基座 / 微调后模型**三条臂，
并**强制并列三条常量基线**。

一句话结论：**微调确实把判别力做出来了，但增益集中在规则失效的那一段；出了这个域，它比「全判多数类」更差。**
内行的部分不是"提升了多少"，而是那个**边界**——以及为了把这条边界说清楚而必须搭起来的那套东西
（判据表可执行化 / 反模板数据 / 双裁判软标签 / 按命令分组切分 / 缺预测即中止的回填门禁）。

入口：[`t5-finetune/README.md`](t5-finetune/README.md) · 完整报告：[`t5-finetune/REPORT.md`](t5-finetune/REPORT.md)

## 方法摘要

- **SQ0 判断点盘点**：从 12,955 次工具调用归纳 7 类判断点 × 五维打标（可枚举性 / 错误代价 / 真值可得性 / 频率 / 上下文依赖）→ 反直觉发现：占比最高的判断（编辑定位 22.7%）恰恰最不该外包
- **SQ1 六臂对照**：本地检查点 × 3 + 大模型 prompted 基线 × 2 + 不外包
- **SQ2/T2**：结果核验（noul 二分类，真值 = exit code）——30 条真实配对
- **统计口径**：干净真值分层 + 敏感性检验 + 单点 Wilson CI；标注侧用双裁判（Cohen's Kappa 0.816，人工复核 41 → 6 条）+ Dawid-Skene EM 多路标注建模

## 结果

见 [`results/summary.md`](results/summary.md)（由 `scripts/make_summary.py` 从原始结果文件重算）。核心：

| 臂 | 判断者 | 准确率 | deny 召回（高危拦截）|
|---|---|---|---|
| A | Laya multilingual（本地 322M）| 58.2% | 61.5% |
| B | Laya english | 34.5% | 0% |
| D | Laya typed-decisions（官方微调检查点）| 27.3% | 0% |
| E | GLM-5.3-Flash（prompted）| 86.8% | 100% |
| E2 | DeepSeek-V4-Flash（prompted）| 96.4% | 100% |

结果核验（T2，30 条）：Laya multilingual **漏判失败 15/15**（把失败全判成功）；GLM 96.6% / DeepSeek 100%。

## 与官方口径的差异（必读）

本仓库测的是**域外零样本可用性**，与官方 README 的分数**不矛盾、也不可比**：

- 官方 0.766（typed-decisions argmax）= **在基准自己的训练集上微调后**的成绩；官方同一张表上，base 零样本仅 0.362，**低于多数类基线 0.461**
- 官方同表 soft accuracy（完整概率分布）：托管版 0.580 vs Laya 0.471——**「单点准确率赢、概率分布输」**
- 本实测结论「微调检查点换域即常量分类器」与官方 README 自述一致（*"Laya is a fast base to specialise, not a zero-shot decision engine"*）

## 复现

```bash
# 1) 跑 Laya 各臂（需自备环境：pip install 'laya[mcp]'）
#    注意：公开题集为脱敏后的 44 条，与文中 55 条相差 11 条（因隐私剔除），故 n 与文中不同
HF_ENDPOINT=https://hf-mirror.com python3 scripts/run_t1.py

# 2) 脱敏规则复跑核验（可验证公开题集确实不含个人信息）
python3 scripts/redact_public.py
```

> **关于 `make_summary.py` / `recompute_all.py`**：这两个脚本是**指标计算方法的透明实现**（公开的 `results/summary.md` 就是它们的输出），但它们读取的是**逐条原始判定记录**——该记录含个人工作流的完整命令与输出，**未随包发布**，因此在干净克隆里无法直接运行。
> 已公开的是**聚合结果**（`results/arms.json`）：每个臂的 n / 准确率 / deny 召回 / ask 召回，可直接引用或自行做二次统计。
> prompted 基线（GLM / DeepSeek）与双裁判标注的脚本同样未发布（依赖作者的第三方推理端点与密钥）。

## 诚实边界

- n=55 / n=30，**方向级结论**，非统计显著；真值清洗后做过敏感性检验，排序不变
- 任务族单一（命令安全 + 结果核验），**不能外推到该模型训练域内的任务**
- 被测大模型经第三方推理端点，分数以脚本原始输出为准
- 只测了「域外可用性」，**没有**验证官方 0.766 本身（那需要在其训练域内复现）
