# T5 评测报告：命令安全三档判定（造数据 → 微调 322M → 评测闭环）

> 版本、数据冻结时刻、模型指纹**全部在 §5 的自动生成区块里**（本行刻意不写死，避免随重训漂移）。

## 1. 一句话

把一个**只读的** 322M 文本编码器基座，在自造的「命令 + 工作目录 + 备注」样本上做 RLCD 微调，
让它对每条命令输出 `allow / ask / deny` 三档之一；在**同一份留出集**上，微调模型在严格命中与平衡准确率
两项上**同时越过**未微调基座、手写正则臂与三条常量基线。**具体数字只出现在 §5 的回填区块里**
（那个区块由 `synth/refill_docs.py` 从预测文件生成，正文不重复任何会漂的数字）。

## 2. 任务与判据

- **输入**：一条待执行命令 + 工作目录 + 一句备注（真实臂另带对话上下文，见 §9 局限）。
- **输出**：`allow`（直接执行）/ `ask`（执行前向用户确认）/ `deny`（拦截不执行）三选一。
- **判据表**：三轴 × 17 条规则 —— 动作（读/写/改/移动/销毁/外发/提权/进程/远控）× 可恢复性（无/有版本控制/脏工作区）× 影响半径（临时 < 单文件 < 目录 < 项目 < 家目录 < 系统 < 远端）。
  详见 `rubric-command-safety.md`；每条规则标注了锚点条数与是否可达。
- **可选集口径（关键）**：真值不是一个点，是一个**可接受集合**。用户政策为
  「不可逆/高危 → {ask, deny}；其余 → {allow, ask}」——即允许「问一下」与「放行」并列成立。
  评测因此以**容忍命中**为业务口径、以**严格命中 + 平衡准确率**为判别力口径。

## 3. 数据

| 集合 | 来源 | 说明 |
|---|---|---|
| 训练 | 合成（抗模板改写）+ 真实会话（脱敏） | 冻结指纹记于 `data/FREEZE.json`；规模见 §5 区块 |
| 留出 | 同上，**按命令串分组切分** | 与训练集命令串重叠 **0**（硬断言，见 §10） |
| 域外 | 另一任务的检索筛选判断 | 只用于退化方向检查，不参与调参 |

- **真值来源**：双裁判（两个与基座不同源的模型）逐条判定 —— 一致则采信，分歧则按用户政策归入 `acceptable` 集合并降级标注（`truth_tier`）。
  训练标签是**软标签**（在可接受集合上做分布），不是 one-hot。
- **切分纪律**：按命令串分组，同一条命令的所有改写/多语境变体同进同出；跨 split 重叠有硬断言。
  留出集**不含**用户仲裁过的 `judge_strict` 条目（裁判比用户政策更严的那 21 条只在训练集）——即留出集比训练集更干净，这一点对结论是**有利**偏向，须一并披露。
- **脱敏**：真实臂命令与路径经规则替换。**推上 Kaggle 的裁剪副本**只含 5 个字段（`id/state/questions/gold/weight`）；
  **公开的合成分集**另含 `acceptable/truth_tier/axes/provenance`（见 `publish/README.md`），两者不是同一份。
  **原始 jsonl 与逐条判定记录一律不公开**（出口管控）。

## 4. 方法

- **基座**：Laya multilingual（322M 编码器）。
- **配方**：官方 RLCD —— proper-scoring-rule 奖励 + GRPO 式策略梯度 + 软交叉熵。训练项由 `laya.common.build_training_item` 构造，软标签以**选项名为键的字典**给出。
- **类别平衡**：靠**条目复制**，不靠样本权重（`weight` 字段仅作血缘备注，训练不读）。
- **梯度更新条数**：入集条数 ≠ 梯度条数——训练脚本会把约 1/10 划作**温度拟合集**（`min(400, N//10)`），
  实际参与梯度更新的条数比入集少几十条。三个数都在 §5 区块的「数据规模与指纹」里列出，别引用混了。
- **置信度**：训练**做了温度缩放拟合**（`rl_agent_config.json` 里首个温度 ≠ 占位值即为拟合证据），但**未测 ECE**；本报告全部结论只依赖 argmax，不依赖 `confidence`。
  基座本身会打出「温度值越界、相关条目置信度视为未校准」的运行时警告——那是基座的问题，不是本次微调的产物。

## 5. 评测口径（v2，外部复核后定稿）

第一轮的教训：`ask` 在两个可选集里都出现，于是「常量 ask」把 容忍命中（100%）、危险漏放（0）、误杀（0）三项头条**全部追平甚至超过微调模型**。

v2 因此规定：

1. **强制并列三条常量基线**（常量 ask / deny / allow）—— 任何不并列基线的表都是误导。
2. 头条换成 **严格命中** 与 **平衡准确率（macro-recall）**；容忍命中降为业务口径脚注，并标注其上界 100%。
3. 危险漏放 / 误杀仍报，但注明其在常量 ask 下同样为 0，**只证明「未过度保守」，不证明判别力**。
4. **分层**报：`rulefail` 层 = 手写正则会判错的题，`general` 层 = 正则不失效的题（条数见 §5 区块）。
   注意两层各有一条**同义反复**：正则臂在 `rulefail` 层恒 0%，在 `general` 层容忍恒 100%——
   正则臂的证据只存在于「全量」与「rulefail 层」。
5. **缺预测计为错**，分母恒等于集合大小。任何一条预测缺失都会让回填脚本**中止**而不是静默缩分母
   （第一轮 A3 的静默缩分母缺陷在 v10 前的文档里真实发生过，见 §8）。

## 6. 怎么读这张表

- 「严格%」与「平衡%」是**唯二**区分模型与常数的列。常量 ask 的严格命中看着低，但它的容忍命中是 100%（上界）——不要用容忍列比较模型与基线。
- 平衡准确率按类召回求平均。留出集类别不均衡，因此严格命中会奖励多数类。
- **每一层都要看一眼该层的常量基线**：`rulefail` 层的标签分布本身偏斜（deny 占多数），
  于是「常量 deny」在该层的严格命中**高于**微调模型与未微调基座——这是层的构成问题，不是模型的成绩。
  引用该层数字时必须连同常量行一起引用。
- **微调并不是在每一层、每一个指标上都赢**（照实说）：
  - `general` 层：微调在严格与平衡两项上都明显高于基座**和**手写正则臂；
  - `rulefail` 层：微调与基座在**严格命中上打平**，赢在平衡准确率（即它在该层把三档都分开了，
    而基座只押多数档）；该层「严格最高」的是常量 deny，谁也不该拿它当成绩。
- **手写正则臂比想象中强**：在这份留出集上它的平衡准确率明显高于未微调基座，
  在 `general` 层甚至接近微调模型。它的短板集中在 `rulefail` 层（那些题按定义就是它判错的），
  以及边界情形（把该问的判成拦、把该放的判成问）。这正是「要微调、但微调不是万能」的完整图景：
  规则覆盖得到的部分它够用，规则失效的部分才需要模型。
- 具体数值见 §5 区块——本节的相对关系以该区块为准，重训后请重新核对本节措辞是否仍然成立。

## 7. 域外退化（E2）

同一模型直接拿去做另一域的判断（检索结果是否有用，二分类）。**数字与混淆矩阵见 §5 区块的 E2 段**，这里只说结论：

微调模型在域外的准确率**低于「全判有用」这个多数类基线**。要说清**它是怎么错的**——
不是"漏掉了那个唯一的负类"这种听起来无伤大雅的说法，而是**把大量正类判成了负类**：
它的负类判定几乎没有一条是对的。也就是说，微调不是让它在域外"稍微变差"，而是**换了一种错法**。

这条是负结果，写进来是因为它是本次工作最该被记住的结论之一：窄任务微调会**收窄**基座的行为面——
它在这个域里学到的是一个很窄的决策边界，出了这个域就退化成偏置。

**v11 的分数低于已作废的 v3**。原因不是「数据更难了」这类未经验证的解释，而是三条可核查的差异：
① v3 的标签是退化的 one-hot（约 40 条分歧样本被压成常量 ask），评测里那部分恰好讨巧；
② 数据规模与分组切分都变了，留出集与 v3 评测用的不是同一份；
③ 口径从 v1（容忍口径）换成 v2（严格 + 平衡）。
两条曲线**不可比**。作废模型存于 `models/_archive/`，仅作对照，任何报告数字不得来自它。

### 8.1 第二轮外部复核抓出的三处静默错误（均已修）

1. **数字漂移（分母静默缩水）**：v10 前的文档里，E0 与 E-rule 两行用的预测文件是 held-out 重建**之前**的旧集
   （只覆盖 41/100 个 id），而表头写的是「held-out 100 条」——同一张表里 E1 是 100 条、E0/rule 是 41 条。
   复核以**表内自证**的方式抓出（general 层只有 74 行，不可能出现 66.7% 这个值）。
   现已在回填脚本里改成「缺任何一条预测即中止」。
2. **文档被掏空**：回填脚本的调用点写成 `open(p,"w").write(replace_region(p, ...))` —— `open(p,"w")` **先截断**，
   随后读到的已是空文件，于是每次回填都把标记区间之外的正文全部擦掉。三份对外文档一度只剩数字块
   （40/6/10 行）。修法：先读后写 + 区间外正文低于阈值即拒写。
3. **切分非确定性**：切分时对 `set` 直接 `shuffle`，而字符串哈希每进程随机化（`PYTHONHASHSEED`）——
   **同参数重跑会得到不同的数据**（实测 687 vs 691 行，留出集只有 38/100 重合）。
   这意味着「照 README 重跑脚本复现冻结数据」根本不成立。修法：`sorted()` 后再 shuffle；
   现在四个不同哈希种子跑出的数据逐字节相同。

### 8.2 v10 → v11 的数据层修正

- **切分确定性化**（上面第 3 条）；
- **`judge_strict` 层编码**：该层是「裁判判得比用户政策更严」的条目（政策允许 allow/ask）。
  v10 把它们按裁判原判 one-hot 成 `deny` 送进训练——与它们自己的 `acceptable` 集合和用户政策**直接矛盾**
  （21 条，占训练集约 3%）。v11 改为在可接受集内均匀编码，与其余软标签层一致。
- 顺带修掉 6 条把**解释器路径当工作目录**的畸形样本（`cwd=/usr/bin/python3`）。

## 9. 局限（先读这一节，再引用上面的数字）

1. **真实臂不可复核**：真实会话臂的真值依赖未公开的对话上下文，公开版只有合成臂可复核。
2. **裁判措辞与判据表曾分叉**：生成真值的裁判 prompt 早期写「覆盖关键文件」，判据表与训练/评测写「清空关键配置」——
   而判据表把「覆盖 ≠ 清零」列为最易写错的边界之首。影响面已量化：全部判定记录里只有 **4 条**的裁判理由
   引用了旧措辞，其中 3 条是 `judge_strict`（在 v10 里被 one-hot 掉、在 v11 里按可接受集编码）、1 条是 allow 共识，
   因此对训练目标的净影响为 **0 条**，留出集里 0 条。裁判脚本现已硬依赖判据唯一真源，但**已生成的判定未按新措辞重判**。
3. **样本量小**：留出集只有一百条量级，**一个条目 = 1 个百分点**；分层后每层只有几十条，单格差异不足以支撑强结论。
4. **合成占多数**：训练集里合成样本是被模板生成后又用另一模型改写去模板化的，仍可能与真实分布有系统差异。
5. **rulefail 层有一半是同义反复、另一半是偏斜**：该层定义就是「正则失效」，所以正则臂在其上恒 0%；
   而该层的标签分布本身偏斜（deny 占多数），于是**常量 deny 在该层的严格命中高于微调模型**。
   引用该层数字时必须连同常量行一起引用，单看模型那一格会高估它。
6. **环境不完全可比**：模型臂在 Kaggle（CPU、`pip install -U` 不钉版本）评测，基线臂在本地 venv 评测；
   `kernel_sources` 按 slug 引用训练 kernel，不钉 run id。同一张表里的臂**不同环境**。
7. **判据表覆盖不足**（两个论域分别报）：在 **T1 的 55 条**标注上，R6 无实例、R4b 零样本；
   在**组装后的数据集**（train+held-out）上零锚点的是 **R3 与 R6**。文档此前只报前者，与审计报的后者对不上——
   这不是矛盾，是**论域没写明**。规则表的「完整感」是部分虚的。
8. **rubric 自检是拟合度不是外推**：55/55 是「对同批 55 条标注的拟合度」，与留出集的硬锚点共享同一次标注，不独立。
9. **留出集是配额采样**：按层、按标签配额整组选取，**不是随机抽样**——层内类别被配额拉平。
10. **预注册交付项缩水未做完**：最初计划里的 typed-decisions 子集实验未做。
11. **权重本身不可逐字节复现**：训练脚本没有固定 torch 随机源（`manual_seed` 在训练 notebook 里 0 命中），
    GRPO 的探索噪声因此不可复现。**可复现的是数据，不是权重**——同一份数据重训会得到不同的权重文件。
12. **上游生成环节也不可复现**：改写器用 `abs(hash(id))` 选风格（受 `PYTHONHASHSEED` 影响）且按线程完成序落盘。
    所以「可复现」的准确边界是：**从 `data/*.jsonl` 到训练数据**这一步可复现，再往上游不行。
13. **`rulefail` 层的层标签在脱敏**前**的命令串上算，而规则臂跑的是脱敏**后**的串**。
    两者本该是同一个字符串。实测有 **1/25 条**（`syn-0213`）因此落在层里却规则臂判它可接受，
    于是该层「正则臂恒 0%」这个构造性说法**不成立**（实测容忍命中 4.0%）。
    层内数字请连同常量基线一起引用，不要把 4.0% 读成模型的成绩。
14. **公开的合成分集不是冻结训练集的子集**：它多 9 条（`synx-*`，来自另一批改写件），
    且家目录路径已被改写。**用公开集重跑得不到本报告里的这份权重**——它只用于复核判据与数据形态。
